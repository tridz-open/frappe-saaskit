# Template site

<p className="lede">Every new tenant starts as a restore of your template site: a prepared site you snapshot once and clone per customer.</p>

The backup of the template site is what a Template's `backup_source` points at. This page was previously called "golden backup"; the idea has precedent in Postgres template databases, WordPress multisite site templates and the DevOps "golden image".

## Why a template site

New sites are restored from a prepared site instead of installing apps from scratch for every tenant, so they arrive fast, identical and pre-configured.

## Integrity

Parts restored from a bucket are sha256-verified.

## Cross-server restore

fcctl streams the backup files into a chunked upload on the target, one 8 MiB chunk at a time, in constant memory. A re-run resumes.

## Making one

<Steps>

### Build the template site

Install your apps and seed data on a site.

### Take a backup

```bash
fcctl backup create <site> -s <server>
```

### Reference it in the Template

Put it in the Template's `backup_source`.

### Test

Provision a throwaway tenant from it.

</Steps>

<Badge status="untested" /> This procedure is not documented end to end upstream. Try it on throwaway sites.

> [!WARNING]
> A template site backup is copied into every tenant. Never leave real customer data, live keys or personal accounts in it.
