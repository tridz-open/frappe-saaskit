## Who owns what

| Layer | Repo | Language | Owns | Talks to |
|---|---|---|---|---|
| Starter | `frappe-saaskit-starter` | TypeScript, React 19, Vite 8 | Landing, pricing, signup, checkout, provisioning progress and the customer console | The saas_core HTTP API, through the SDK |
| SDK | `saas_core/sdk` | TypeScript, ESM | `@frappe-saaskit/client`, `react`, `mock` (plus experimental `vue`, `node`); types generated from `openapi/v1.yaml` | saas_core |
| Control plane | `saas_core` | Python, a Frappe v16 app | Plans, templates, tenants, subscriptions, billing, provisioning jobs and the HTTP API `2.0.0-alpha.1` | Payment gateways, fcctl |
| Driver | `fcctl` | Python 3.11+, CLI and library | The only thing that talks to Frappe Cloud: sites, apps, backups, tasks, plus a safety layer | Frappe Cloud v2 |
| Platform | Frappe Cloud v2 | n/a | **Central** (dashboard.frappe.io: team, billing, servers, snapshots, buckets) and **Pilot** (the per-server gateway: sites, apps, backups, tasks, logs) | n/a |

## Three rules

<FeatureGrid cols={3}>
  <Feature icon="LayoutDashboard" title="Frontends only call the saas_core API">The starter and the SDK are one such frontend. The contract is a versioned OpenAPI file.</Feature>
  <Feature icon="Plug" title="Gateways call back into webhooks">Payment providers confirm payments by signed webhooks. Each one is stored once as a Payment Event.</Feature>
  <Feature icon="Server" title="Only the server reaches Frappe Cloud">Only through the fcctl port. The browser never holds a Frappe Cloud credential.</Feature>
</FeatureGrid>

## A request, end to end

<Diagram title="Checkout request flow" caption="The browser proof and the gateway webhook race; the first one to record the Payment Event wins." description="The browser asks the starter to choose a plan and sign up. The customer pays on the hosted checkout. ## Control plane and tenants

One site runs saas_core: the **control plane**. Every customer gets a separate **tenant** site on Frappe Cloud. Tenant servers are shared by default, so many customer sites live on the same bench. Set `saas_core_fc_dedicated_bench=1` to turn on the empty-bench guard, which requires the bench to be empty.
