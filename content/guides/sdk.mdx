# Building on the SDK

<p className="lede">The TypeScript SDK is the typed client the starter uses. Use it to build your own front end.</p>

> [!WARNING]
> The SDK is alpha (`0.1.0-alpha.x`) and not on npm. Expect breaking changes between releases. Pin the exact release you tested.

## Packages

All packages share one version and are ESM-only. Every call goes to `<site>/api/method/saas_core.api.v1.<operation>`; types are generated from `openapi/v1.yaml`.

| Package | Status | What it is |
|---|---|---|
| `@frappe-saaskit/client` | <Badge status="alpha" /> core verified | Framework-free typed client. Typed errors, safe retries, CSRF handling |
| `@frappe-saaskit/react` | <Badge status="alpha" /> core verified | `SaasProvider`, TanStack Query hooks, Razorpay Checkout.js helper |
| `@frappe-saaskit/mock` | <Badge status="alpha" /> | In-memory saas_core lookalike for tests, demos and UI work |
| `@frappe-saaskit/vue` | <Badge status="experimental" /> | Vue 3 composables; no consumers yet |
| `@frappe-saaskit/node` | <Badge status="experimental" /> | Helpers for Node scripts and CLIs |

## Install from release tarballs

`R` is the saas_core release tag, `V` the SDK version. Pin both.

```bash
R=0.1.0-alpha.3   # saas_core release
V=0.1.0-alpha.4   # SDK tarball version
B=https://github.com/tridz-open/saas_core/releases/download/v$R

pnpm add "$B/frappe-saaskit-client-$V.tgz" "$B/frappe-saaskit-react-$V.tgz" \
  @tanstack/react-query react react-dom
pnpm add -D "$B/frappe-saaskit-mock-$V.tgz"
```

The other packages depend on `@frappe-saaskit/client`, which is not on the registry, so pin it with an override and the same version string (npm users: top-level `"overrides"`):

```json
{
  "pnpm": {
    "overrides": {
      "@frappe-saaskit/client": "https://github.com/tridz-open/saas_core/releases/download/v0.1.0-alpha.3/frappe-saaskit-client-0.1.0-alpha.4.tgz"
    }
  }
}
```

Each release has a `SHA256SUMS` asset. Requirements: Node.js 20+, pnpm 9+.

## Quickstart

`baseUrl` is the site origin, not an `/api` path.

```ts
import { createClient } from '@frappe-saaskit/client';

const client = createClient({ baseUrl: 'https://app.example.com', auth: { type: 'cookie' } });
const me = await client.me.get().catch(() => client.auth.login({ email: 'me@example.com', password: '...' }));
const plans = await client.plans.list();
const { tenant, job } = await client.tenants.create({ slug: 'acme', plan: plans[0]!.code });
const sub = client.subscribe({ jobId: job.name }, (e) => console.log(e.type, e.data));
```

Billing is preview first, then apply: `client.billing.previewCancel(tenantId)` then `client.billing.cancel(tenantId, { reason })`.

## React

`SaasProvider` wraps your app and mounts a TanStack Query client. Hooks include `useMe`, `usePlans`, `useCheckout`, `useRazorpayCheckout`, `useJob`, `useTenantLive`, `useCancelSubscription`, `usePreviewCancel` and `usePreviewChange`. See the [SDK README](https://github.com/tridz-open/saas_core/blob/main/sdk/README.md#quickstart-react) for a full component.

## Mock backend

```ts
import { createMockFetch } from '@frappe-saaskit/mock';

const fetch = createMockFetch({ stepMs: 0 }); // no network, no MSW
const client = createClient({ baseUrl: 'http://localhost', auth: { type: 'cookie' }, fetch });
```

The mock is seeded with a demo user, three plans and a tenant. It is a simulation, not a contract test.

## Verified vs experimental

Verified: auth, catalog and config, tenants (list, get, create, slug check), jobs, Razorpay `order` checkout, beta access, and the billing cancel and upgrade flows. Everything else is <Badge status="experimental" />. The full matrix is in the [SDK README](https://github.com/tridz-open/saas_core/blob/main/sdk/README.md#verified-vs-experimental).
